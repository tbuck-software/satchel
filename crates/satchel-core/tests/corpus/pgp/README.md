# OpenPGP corpus

GnuPG 2.5.21 generated this Ed25519/CV25519 key, detached signature and
encrypted messages on 2026-08-29. One message uses GnuPG's default compression,
the other forces BZip2. The private key passphrase is
`fixture-passphrase`. These files contain test-only key material.

The native rPGP tests consume the fixtures without starting `gpg`. Live GnuPG
round trips remain in `tests/pgp_interop.rs` and skip when the optional binary
is absent.

`rpgp-cv25519-import.sec.asc` is a separate test-only key generated by Satchel's
rPGP engine. Its passphrase is `interop-test-passphrase`; the paired ciphertext
decrypts to `GnuPG control plaintext\n`. The interop suite checks the first
GnuPG decrypt after importing this key and also rejects a wrong passphrase.

GnuPG 2.4.8 with libgcrypt 1.12.0 can report `Bad passphrase` for the correct
passphrase on this CV25519 key. The underlying `gcry_pk_testkey` returns
`Bad secret key`. Upstream tracked an ECC validation regression in
[T8094](https://dev.gnupg.org/T8094.html) and fixed it in
[libgcrypt 1.12.1](https://github.com/gpg/libgcrypt/blob/master/NEWS).
On this host, ten fresh imports failed their first decrypt with system
libgcrypt 1.12.0; ten passed with an isolated libgcrypt 1.12.2. A lookup flag
also changed the outcome on the old library, but failed again under harmless
instrumentation, so it is not a product workaround.

`inline-covered.eml` and `inline-two-blocks.eml` are `text/plain` mails with
inline armor that GnuPG 2.4.8 encrypted to the fixture's public key on
2026-10-30. Encrypting needs only the public key, so the libgcrypt issue above
does not affect them. The first holds one block between a cover note and a
suffix; its plaintext is `Hello Bob,\n\nthe meeting moves to Thursday.\n`,
without MIME headers. The second holds two blocks after a cover note, and
Satchel refuses to decrypt it rather than show one block as the decrypted
message. The app tests in `src-tauri/src/commands/{pgp,messages}.rs` read these
and the fixtures below.

GnuPG 2.4.8 with libgcrypt 1.12.2 produced three more fixtures on 2026-10-30,
each encrypted to the fixture's public key:

- `mime-mixed-parts.eml` is PGP/MIME whose plaintext is
  `../decrypted/mixed-text-attachment-text.eml`: text, a PDF, text. Both text
  parts must be shown and the PDF listed.
- `signed-covered-block.eml` is `multipart/signed`, signed by the fixture key,
  whose signed text holds a cover note and one armored block. The signature
  covers the ciphertext, not the plaintext the reader shows after decrypting,
  so it may only count as a partial signature.
- `quoted-foreign-block.eml` is a reply that quotes
  `rpgp-cv25519-import.enc.asc`, a block for another key, with `> ` prefixes.
  The fixture key cannot decrypt it; only that block may say so, not the
  message.

To require the optional GnuPG tests on a host with the affected library, run
them against a newer libgcrypt in a scoped environment; do not replace the
system library just for the test:

```bash
SATCHEL_REQUIRE_GPG=1 LD_LIBRARY_PATH=/path/to/libgcrypt-1.12.2/lib \
  cargo test -p satchel-core --test pgp_interop -- --test-threads=1
```
